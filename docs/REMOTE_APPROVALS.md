# Remote owner approval — controlled single-process pilot (Issue #23)
**Default:** `create_from_env()` and normal `local-gpt-agent --run` remain read-only/deny-all for remote input. The owner browser portal, owner APIs and `request_device_click` MCP tool are absent unless independently enabled. This is neither a deployed service nor evidence of ChatGPT web controlling a different-location PC.
**Owner consent:** The authenticated `/owner/approve` portal uses a separately registered OAuth public browser client, authorization-code PKCE S256, CSRF state, a pinned HTTPS issuer, `approvals:manage` and in-memory browser bearer. The service enforces that client ID; a model/MCP token cannot approve its own request. For one exact preexisting job the browser calls `navigator.credentials.get` with UP+UV; server verifies P-256 signature, RP ID, origin, challenge, expiration, credential owner and monotonic counter. The independent, operator-enabled `/owner/enroll` page and `/api/owner/passkey/*` endpoints support first-passkey registration; they never issue operator permits, self-approve actions, export receipts or disclose private keys.
**Job proof:** The trusted `RemoteActionRelay` accepts bounded `window.click` coordinates only for a verified `devices:read` + `devices:input` account and an authenticated connected device. Only an independently verified passkey assertion releases the Ed25519-signed 30-second receipt on a device-key-signed `/api/agent/actions/poll`. Receipt binds account, device, session, exact job ID, HWND, capability, canonical action hash and one-use nonce. The PC pins its issuer public key, transactionally consumes the nonce in local SQLite, rechecks pairing and STOP, then invokes the guarded native Win32 adapter. Expired/forged/foreign/changed/replayed jobs deny; uncertain input is never retried automatically.
**Cancellation:** Owner `/api/owner/approvals/deny` cancels a pending job. Owner `/halt` first persists the owner-wide halt in the single-host private SQLite STOP ledger, then cancels queued jobs; device revoke persists denial of new cloud requests. This is **not** an instant cross-host/Windows-wide STOP: the local Windows panel STOP remains authoritative at the PC. The native adapter rechecks actual window/process identity, selected foreground, unlocked user session, UAC/elevation, occlusion, bounds and STOP at dispatch. No focus switching, remote shell, typing, or bypass of OS dialogs is authorized.
## Operator-only HTTPS gateway (POSIX; one worker)
1. Provision a protected issuer once: create a private service-owned mode-0700 directory, then `local-gpt-issuer --create --key-file /private/owner-mcp/issuer.pem` (exclusive 0600 key). `--show-public` with the same key path prints **only the public pin**. Never upload private PEM to the PC, ChatGPT, a repository or a browser. Symlinks, shared permissions, wrong algorithms, missing or malformed private keys deny startup.
2. Configure a separate real OAuth authorization server with RS256 JWKS and the `https://gateway.example/mcp` audience; register an owner browser public client with PKCE, exact callback `https://gateway.example/owner/approve`, `approvals:manage`, CORS token exchange, and a distinct MCP client with `devices:read`/`devices:input`. Approval endpoints pin the owner's verified OAuth client ID. No model-controlled request or bearer substitutes for a real passkey.
3. Supply `LOCAL_MCP_RESOURCE_URL`, `LOCAL_MCP_ISSUER_URL`, `LOCAL_MCP_JWKS_URL`, `LOCAL_MCP_STOP_DB=/private/owner-mcp/stop.sqlite`, `LOCAL_MCP_REMOTE_APPROVALS=1`, `LOCAL_MCP_REMOTE_SINGLE_PROCESS_ACK=1`, `LOCAL_MCP_APPROVAL_SIGNER_FILE=/private/owner-mcp/issuer.pem`, `LOCAL_MCP_PASSKEY_DB=/private/owner-mcp/passkeys.sqlite`, `LOCAL_MCP_OWNER_CLIENT_ID=<owner-browser-client>`, `LOCAL_MCP_OWNER_AUTHORIZE_URL=https://issuer.example/authorize` and `LOCAL_MCP_OWNER_TOKEN_URL=https://issuer.example/token`. To activate first-passkey browser registration in this same single-worker pilot, independently add `LOCAL_MCP_OWNER_ENROLLMENT=1`, `LOCAL_MCP_OWNER_SINGLE_PROCESS_ACK=1`, `LOCAL_MCP_OWNER_PERMIT_DB=/private/owner-mcp/permits.sqlite`. Provision the three private databases and the issuer key beforehand; see [owner bootstrap](OWNER_BOOTSTRAP.md) and [credential store](PASSKEY_REGISTRATION.md). Missing/unsafe configuration fails closed; all optional modes default OFF.
4. A trusted operator independently verifies the owner and issues a short-lived, single-use registration permit **only from the private host terminal** (`python -m local_gpt_mcp.policy.bootstrap issue /private/owner-mcp/permits.sqlite <verified-owner-sub>`). The owner visits `/owner/enroll` from their own browser, signs in with the dedicated OAuth client and `owner:enroll` scope, enters the operator-issued permit, and uses a real passkey through `navigator.credentials.create`. The verified P-256 public key/counter is stored in the pre-provisioned private database and can then be used for one-action `/owner/approve` assertions with `approvals:manage`. Persisted STOP/revocations, device enrollment and signature nonces are **single-host only**; pending approvals and in-progress registration remain in one process and reset on restart. Never run multiple workers or claim live compatibility until the IdP, browser and physical device have been tested.
## Manual Windows startup and STOP
1. Pair with `local-gpt-agent --gateway https://gateway.example --pair` using a real one-time authenticated owner enrollment. Locally and independently verify the issuer's public pin, then install its 44-character padded URL-safe base64 text in the Windows user's `owner-issuer.pub` alongside the private DPAPI-protected device credential; never accept a pin from an MCP argument or untrusted webpage.
2. While physically present, select an exact safe HWND and run `local-gpt-agent --gateway https://gateway.example --run-approved-input --owner-id <jwt-sub> --window-handle <HWND>`. Foreground the window during local selection. The visible native Tk safety panel requires a typed pairing challenge; decline or close to deny. No autostart, listener, or persistence of physical pairing after restart is installed.
3. Leave the selected unelevated window in the unlocked interactive user session; lock/UAC, foreground changes, replaced windows, disconnect, missing receipts or STOP deny. Later clicks still require independent owner-passkey approval on the trusted browser/phone. Emergency STOP on the PC revokes locally; cloud halt alone cannot guarantee stopping an already dispatched or disconnected PC.
## Release conditions
**Still unverified:** live operator/IdP deployment, actual physical owner passkey registration and assertion from a second device, issuer rotation and revocation, distributed queue/STOP, real Windows lock/UAC/STOP and accessibility acceptance, signed install artifacts and actual supported ChatGPT-web-to-PC usage from a different location. Keep Issue #23, Issue #24, and all high-risk `DNS_REBINDING_TOCTOU`, `PHYSICAL_WINDOWS_ACCEPTANCE`, `WEB_REMOTE_E2E` blockers OPEN; do not merge the draft PR or release to `main` on simulated CI alone.

**Credential storage after Issue #39:** remote approval startup never creates or chmods the owner passkey database. Provision the private POSIX `SQLiteCredentialStore` explicitly using `docs/PASSKEY_REGISTRATION.md` before setting `LOCAL_MCP_REMOTE_APPROVALS=1`. Prior pilot auto-created databases cannot be silently trusted or migrated because deleted IDs and revoked credential history cannot be recovered. Missing, legacy or insecure databases now deny startup. This adapter preserves existing owner-presence API errors without duplicating database operations; independent browser/operator enrollment and Windows acceptance are still required.
